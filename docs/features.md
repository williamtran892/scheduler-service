# Features

This page lists the behaviour the system delivers today. Each entry links to the Gherkin features
that prove it. Update it in the same change that delivers or alters a feature.

| Feature | What it does | Proven by |
|---|---|---|
| Health check | `GET /healthz` reports whether the service can reach its database | `features/health.feature` |
| Book an appointment | `POST /appointments` confirms an appointment for a customer's vehicle on one compatible bay and one qualified technician, claimed in one transaction so a bay or technician is never double-booked; repeating a booking returns the same appointment; refusals are problems with a stable code and, for a taken slot, nearby alternatives. `GET /appointments/{appointmentId}` reads it back with the ledger cells it owns and, on request, its audit trail. The caller states its channel in `X-Channel`, which decides the staff or customer view | `features/booking.feature`, `features/claim_ledger.feature`, `features/idempotency.feature`, `features/concurrency.feature` |
| Appointment lifecycle | Six transitions after booking, each one transaction that honours the `expectedVersion` the caller last saw, changes the ledger as the state machine says, appends an audit event and an outbox row, and returns the record. `POST /appointments/{appointmentId}/reschedule` moves a confirmed appointment in time, to another bay or technician, or both, claiming the new cells with its own counting as free and releasing everything outside them, all or nothing, under booking's rules (a customer may move in time only). `.../cancel` and `.../no-show` release every cell; `.../check-in` and `.../start` leave the ledger alone and start records the actual start; `.../complete` records the actual end and frees the cells from the current grid cell on, so an early finish can be sold to a walk-in. A no-show who turns up is checked in onto whatever pair is free from the current grid cell, or refused with `SLOT_TAKEN`. A background sweeper marks a confirmed appointment `NO_SHOW` once its start plus a grace period has passed. Refusals are problems with a stable code (`VERSION_CONFLICT`, `INVALID_TRANSITION`, `FORBIDDEN` for a customer channel asking for a staff action) and change nothing | `features/lifecycle.feature`, `features/reschedule.feature`, `features/noshow.feature` |
